**한국어** · [English](README.en.md)

사회과학 논문을 처음부터 끝까지 대신 써 주는 [Claude Code](https://claude.com/claude-code) 플러그인입니다.

주제를 알려주시면 연구 질문과 가설을 세우고, 선행연구를 찾고, 본문을 쓰고, 투고할 수 있는 워드 파일(`.docx`)과 마크다운으로 만들어 드립니다. 역할이 다른 여섯 개의 AI가 나눠 맡는데, 그중 하나는 **검사만 하는 역할**입니다. 글을 쓴 AI가 자기 글을 스스로 통과시킬 수 없게 만든 것이 이 플러그인의 핵심입니다.

## 무엇이 다른가요

이 플러그인이 지키는 것은 문장이 아니라 **인용**입니다. 인용 오류는 읽어서는 잘 안 걸리고 **하나씩 대조해야 걸립니다.** 본문에 달린 인용을 참고문헌 목록과 맞춰 보고, 반대로 목록에 있는 항목을 본문에서 다시 찾아봐야 나옵니다. 이런 것들이 나옵니다.

- **실제로 없는 논문을 인용한 것** — 그럴듯한 저자와 연도가 붙어 있어서 읽어서는 티가 안 납니다
- **참고문헌에는 있는데 본문 어디에도 안 쓰인 출처** — 쓰다가 덜어낸 문단의 흔적입니다

마감 직전에 가장 하기 싫은 일이고, 그래서 실제로는 잘 안 하게 되는 일입니다. 이 플러그인은 그걸 기계적으로 합니다.

| | 일반 Claude Code | 이 플러그인 |
|---|---|---|
| 인용을 대조하나 | 인용이 달린 채로 끝 | 본문과 참고문헌을 **하나씩 전부** 맞춰봄(부록 포함) |
| 누가 검사하나 | 쓴 AI가 자기 글을 봄 | **다른 AI**가 파일을 다시 읽고 검사 |
| 작업 과정이 남나 | 원고 파일 하나 | 설계·점검 결과·근거 목록·검수 기록이 파일로 남음 |

한 가지는 솔직히 말씀드리겠습니다. 위 표는 **구조를 설명한 것이지 직접 재본 수치가 아닙니다.** 이 플러그인은 일반 Claude Code와 나란히 돌려 비교하는 실험을 아직 하지 않았습니다. 같은 방식으로 만든 자매 플러그인에는 그 실측 기록이 있으니 그쪽을 참고해 주세요.

## 어떤 순서로 진행되나요

```
연구설계 → 🚦1차 점검 → ★목차·가설 확인 요청 → 자료 조사와 데이터 분석(동시에) → 본문 집필 → 🚦2차 점검 → 교정 → 워드 파일
```

중간에 **두 번 멈춰 섭니다.** 첫 번째는 쓰기 전에 방향을 보는 자리입니다. 확인할 방법이 없는 가설, 답이 나올 수 없는 연구 질문, 말로만 있고 실제로 무엇을 어떻게 잴 것인지가 정해지지 않은 개념 — 이런 것들을 여기서 걸러냅니다. 그대로 두고 본문을 다 써 버리면 되돌릴 방법이 없기 때문입니다.

두 번째는 다 쓴 원고를 검사하는 자리입니다. 완성된 글은 그럴듯해 보여서 스스로 의심하기 어렵기 때문에, 글을 쓰지 않은 **다른 AI**가 검사합니다. 이 AI는 **읽기만 하고 고치지는 못합니다.** 고칠 권한이 없으니 슬쩍 넘어갈 수도 없습니다.

검사는 다섯 가지를 봅니다. ①연구 질문과 가설에 실제로 답했는지 ②인용과 출처가 진짜인지 ③앞뒤 논리가 맞는지 ④연구 방법이 타당한지 ⑤한국어 문장이 매끄러운지. 이 중 ②가 중심입니다. 숫자를 많이 다루는 논문(통계 분석, 인용 데이터 분석 등)에는 더 깐깐한 검사가 따로 준비되어 있습니다 — 무엇을 어떻게 쟀는지, 인과관계를 주장할 만한 근거가 정말 있는지, 결과를 문장으로 옮기면서 과장하지 않았는지를 봅니다.

실제로 이 점검에서 걸린 것들입니다. 없는 논문을 인용한 것 2건, 참고문헌에만 있고 본문에서 안 쓰인 출처 1건.

인용이 진짜인지만 보지 않고 **그 논문이 정말 그 말을 했는지**도 봅니다. 본문을 쓰는 AI가 인용마다 출처의 몇 쪽, 어느 문장인지를 보이지 않는 표시로 달아 두고, 검사하는 AI가 그 자리를 열어 맞춰 봅니다. 최종 워드 파일에서는 이 표시가 지워집니다.

## 심사를 받은 뒤에도

학술지에서 심사의견이 돌아오면 그다음 일도 맡길 수 있습니다. 심사 대응에서 흔한 실수는 세 가지입니다.

- **빠뜨림** — 한 의견에 요구가 두세 개 들어 있는데 하나만 답합니다
- **말로만 고침** — 답변서에는 "반영했다"고 썼는데 원고는 그대로입니다
- **번짐** — 한 곳을 고치다 요청받지 않은 곳까지 다시 써서 새 문제가 생깁니다

그래서 이렇게 진행합니다. 심사의견을 요구 하나하나로 쪼개 목록을 만들고, 항목마다 **고칠지·일부만 고칠지·반론할지는 직접 고르시게** 합니다. AI는 고르라고 한 자리만 고치고, 고치기 전과 후의 원고를 프로그램으로 대조해 요청 밖 수정을 걸러냅니다. 답변서는 실제로 바뀐 곳만 근거로 씁니다. 마지막으로 수정에 참여하지 않은 AI가 **답변서를 보지 않은 채 원고만 보고** 재심사를 흉내 내어, 말로만 고친 항목을 찾아냅니다.

## 설치

```
/plugin marketplace add parkjui92/socsci-paper-kit
/plugin install socsci-paper-kit@socsci-paper-kit
```

한국어 교정을 제대로 받으시려면 [paper-proofread](https://github.com/parkjui92/paper-proofread)도 함께 설치하시길 권합니다. 없어도 위 다섯 가지 중 교열 검사가 대신 처리합니다.

## 이렇게 쓰시면 됩니다

평소 말하듯 요청하시면 됩니다.

```
플랫폼 노동자 사회보험 논문 써줘. 설문 데이터 첨부했어      ← 데이터가 있을 때
데이터는 없어. 문헌 정리해서 이론 논문으로 쓸 거야          ← 분석 담당이 자동으로 빠짐
이 논문 초안 검수해줘. 인용부터 봐줘                        ← 이미 쓴 원고 손보기
가설을 조절효과 모형으로 다시 짜줘                          ← 확인 요청 단계에서
심사의견 왔어. 정리해서 수정하고 답변서 써줘                ← 학술지 심사 이후
내가 쓴 답변서 빠진 거 없는지 봐줘                          ← 답변서만 점검
```

네 번째 줄처럼, 목차와 가설을 보여드릴 때 고쳐 달라고 하시면 그 자리에서 다시 짭니다. **방향을 바꾸기에 가장 값싼 시점**입니다. 멈춰 서서 기다리는 동안에는 자리를 비우셔도 됩니다.

## 무엇이 남나요

완성된 논문 하나만 나오는 게 아니라, **작업 과정이 전부 파일로 남습니다.**

연구설계안, 1차 점검에서 무엇을 왜 지적했는지, 어떤 사실을 어디서 가져왔는지 정리한 목록, 데이터 분석 결과, 본문 초안, 2차 점검 지적과 실제로 고친 내역, 그리고 최종 워드 파일입니다.

몇 달 뒤 심사자가 "이 인용 어디서 나온 거냐"고 물었을 때 답할 수 있다는 뜻입니다. `_workspace/` 폴더는 지우지 마세요. 나중에 일부만 다시 돌릴 때 이 파일들을 기준으로 움직입니다.

## 알아두실 점

- 워드 파일 변환이 실패하면 마크다운 원고를 먼저 내드리고 직접 변환하는 방법을 안내합니다.
- **점검이 오류를 줄여주긴 하지만 없애주지는 못합니다.** 검사하는 AI도 같은 계열이라 비슷한 착각을 할 수 있습니다. 최종 확인은 사람이 해야 합니다.
- **돈을 내야 볼 수 있는 학술 DB**(DBpia·Scopus·Web of Science)는 여러분에게 접근 권한이 있어야 확인됩니다. 확인하지 못한 인용은 조용히 지우지 않고 `[보강 필요]`로 표시해 남겨둡니다.
- 국내 학술 관행에 맞춰져 있습니다. 교열은 한국어 문장을 다듬고, 검색은 국내 논문이 모여 있는 KCI·RISS·DBpia를 봅니다. 영문 저널에 내실 거라면 이 두 가지를 손보셔야 하고, **나머지는 언어와 상관없이 그대로 씁니다.**
- [설치·설정에서 막힐 때](docs/runtime-notes.md) · [이런 점검 구조를 직접 만들고 싶다면](docs/verification-gates.md)
